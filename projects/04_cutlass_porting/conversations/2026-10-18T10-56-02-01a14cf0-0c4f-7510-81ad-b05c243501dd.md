这里把 `128×256×64` 解释为完整问题的 `(M,N,K)`，计算 FP16 输入、FP32 累加与输出的 `C=A×B`。采用以下分块：

| 层级 | 选择 | 对应结果 |
|---|---|---|
| 完整问题 | `128×256×64` | C 有 32,768 个元素 |
| CTA tile | `64×128×32` | 4 个 CTA，各执行 2 次 K 主循环 |
| CTA 线程 | 128 threads | 4 个 warp |
| MMA atom | SM80 `16×8×16` | warp 协作执行 Tensor Core 指令 |
| atom 排列 | `2×2×1` | TiledMma 基础覆盖 `32×16×16` |
| CTA 内重复 | `2×8×2` | 每线程持有 64 个 FP32 累加元素 |

核心类型配置为：

```cpp
using Mma = decltype(make_tiled_mma(
    SM80_16x8x16_F32F16F16F32_TN{},
    Layout<Shape<_2, _2, _1>>{}));
```

A 使用行主序；数学上的 B 使用列主序，在 CuTe 中以 `(N,K)` 视图表达。因此，全局元素偏移是：

```text
A(m,k)      → 64*m + k
B_view(n,k) → 64*n + k
C(m,n)      → 256*m + n
```

线程映射中，令：

```text
lane = thread_id % 32
wm   = (thread_id / 32) % 2
wn   = thread_id / 64
x    = lane % 4
y    = lane / 4
```

则 C 的线程分片坐标为：

```text
v = v0 + 2*v1，v0/v1 ∈ {0,1}
mi ∈ [0,1]，ni ∈ [0,7]

i = y + 8*v1 + 16*wm + 32*mi
j = 2*x + v0 + 8*wn + 16*ni

global_m = 64*blockIdx.x  + i
global_n = 128*blockIdx.y + j
```

例如，`C(67,141)` 由 CTA `(1,1)` 的 thread 78 持有，其元素偏移为 `67×256+141=17293`，字节偏移为 `69172`。文档进一步展开了乘加项 `A(67,37)×B(37,141)`，包括共享内存偏移，以及搬运线程和 MMA 消费线程的区别。

示例实际执行了 `local_tile → shared memory → partition_A/B → register fragments → gemm → partition_C 写回`，验证结果为：

```text

PASS: all 32768 outputs; max_abs_error=0
```

程序逐项检查了全部线程的手推坐标，并确认 A/B 每个元素被两个 warp 分片复用、C 每个元素恰好覆盖一次。当前测试输入可精确表示，因此本次误差为零。

为便于本机验证，实现选择了 **SM80 warp 级 MMA**。项目现有指南中的 SM100 UMMA 使用不同的数据与线程组织，本文的 lane 公式不能直接套用；文档已说明两者的对应关系。该示例以理解和验证为目的，尚未加入流水线或性能优化。
